# 白读 · ByRead

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
![Python](https://img.shields.io/badge/Python-3.10%2B-blue)
![Platform](https://img.shields.io/badge/Platform-Windows-lightgrey)

给自己用的本地 RSS 阅读器。数据全在你自己的电脑上，不需要登录，没有推荐流，没有广告。

**核心体验**：你在一个输入框里输入博主名或平台名，它自己找到对应的源并开始抓文章。全程不出现"RSS""路由""订阅地址"这些词。

---

## 一、快速开始（怎么自己启动）

**最简单：双击 `start.bat`**（在 `E:\ByRead\` 目录下）

它会依次做四件事：检查 Python → 检查并安装依赖 → 启动服务 → 打开浏览器。
启动后那个黑色命令行窗口**就是程序本体，别关它**；要停止程序，关掉那个窗口或按 `Ctrl+C`。

如果它提示「**白读已经在运行了**」，说明已经有一个实例在跑（可能在另一个窗口里），
它会直接帮你打开页面，不会报错。

**或者手动启动：**

```bat
cd /d E:\ByRead
python app.py
```

看到 `白读已启动 → http://127.0.0.1:5000` 就成了，浏览器打开这个地址。

### 用起来更顺手一点

| 想要 | 怎么做 |
|---|---|
| 桌面快捷方式 | 右键 `start.bat` → 显示更多选项 → 发送到 → 桌面快捷方式 |
| 开机自动启动 | `Win+R` 输入 `shell:startup` 回车，把上面的快捷方式拖进去 |
| 停止程序 | 关掉那个命令行窗口，或在窗口里按 `Ctrl+C` |
| 备份数据 | 复制 `instance\bai_read.db` 这一个文件就够了 |
| 从零开始 | 关掉程序，删掉整个 `instance` 文件夹，重新启动 |

首页地址固定是 **http://127.0.0.1:5000**，只监听本机，同一局域网的其他设备访问不到。
想改成别的地址或端口、或者想让手机也能看，见「**十一、给将来留的口子**」——
那里也写了开放到局域网时**必须**做的哪一件事。

首次启动会自动添加 3 个示例源（阮一峰的网络日志、少数派、Hacker News）并抓一遍，所以你打开就能看到文章，不是空页面。不想要就在设置页删掉。

环境要求：Python 3.10+（本机实测 3.14.2 正常）。不需要 Node，不需要 Docker，不需要联网构建。

## 二、怎么添加订阅（灵魂功能）

首页右上角 **＋ 添加**，或设置页的输入框，五种输入都能认：

| 你输入 | 会发生什么 |
|---|---|
| `半佛仙人` | 搜出 B 站上所有同名的 UP 主，选一个即可 |
| `B站 半佛仙人` | 只在 B 站范围内搜 |
| `少数派` / `知乎日报` / `机核` | 直接命中这个源（20 个预置源任选） |
| `https://space.bilibili.com/37663924` | 识别出这是某个 UP 的主页，直接订阅他 |
| `https://blog.codingnow.com/` | **普通网页也行**：自动在页面里找订阅地址并订上（详见下节） |
| `https://www.ruanyifeng.com/blog/atom.xml` | 已经就是订阅地址，校验后直接添加 |

设置页还有一排"推荐订阅源"，点一下就能加。

### 粘贴任意网址会自动找到订阅地址

粘贴一个普通网页（博客首页、新闻站首页）时，程序会自己去找它的订阅地址，你不需要知道 RSS 是什么：

1. 打开这个网页，先看 `<link rel="alternate">` 里有没有订阅地址（最标准的做法）；
2. 没有的话，依次试 `/feed`、`/rss`、`/atom.xml`、`/feed.xml`、`/index.xml`、`/rss.xml`
   —— 而且会同时拼在**域名根**和**页面所在目录**下面
   （例如 `ruanyifeng.com/blog/` 的源其实在 `/blog/atom.xml`，只试根目录会漏掉）；
3. 还会扫一遍页面里指向 feed/rss/atom 的链接（有些站点只在页脚放一个）。

**每个候选都会被真实抓取解析一次**，只有真能读出文章才会出现在候选列表里 ——
所以**绝不可能把一个普通网页的 HTML 当成订阅源存进库**。找到多个时，会像平台搜索那样弹出候选让你选。

优先级始终是：**预置源 / 平台识别 > 直接粘的订阅地址 > 自动发现**。
所以粘 `https://sspai.com` 仍然走预置的少数派源，不会被自动发现抢走。

**键盘快捷键**（列表页）：

| 按键 | 功能 |
|---|---|
| `[` | 收起 / 呼出侧边栏 |
| `/` | 跳到搜索框 |
| `x` | 进入 / 退出多选 |
| `空格` | 多选模式下勾选当前项 |
| `j` / `k` | 上下选 |
| `o` 或 `Enter` | 打开 |
| `m` | 已读 / 未读（多选模式下等同勾选） |
| `s` | 星标 |
| `f` | 放进收藏夹 |
| `Delete` | 删除这篇文章 |
| `r` | 刷新 |
| `Esc` | 退出多选 / 清除搜索 |
| `Shift + A` | 全部已读 |

阅读页：`s` 收藏，`Esc` 返回列表。

## 三、"无感订阅"能做到什么程度

先纠正一个前提：**"无感"跟 RSSHub 没有必然关系**。RSSHub 只是一堆开源抓取脚本的集合，它做的事我们自己也能做（B 站、知乎日报、机核、GitHub 趋势现在都是原生实现，一次都没经过 RSSHub）。

真正决定"能不能无感"的，是**这个平台的数据从哪来、要不要登录态**。分三层：

### 第一层：自带官方源 / 官方接口 —— 完全无感，零依赖

现在预置的 20 个源里，**17 个属于这一层**，实测全部可用：

| 类别 | 源 |
|---|---|
| 科技媒体 | 少数派、IT之家、爱范儿、极客公园、雷峰网、钛媒体、Solidot |
| 技术博客 | 阮一峰的网络日志、酷壳、云风的 Blog |
| 开发者 | 掘金、GitHub 每日趋势、Hacker News |
| 游戏 / 亚文化 | 机核（文章+电台）、游研社 |
| 平台原生 | 知乎日报、B站热门 |
| 社区 / 影视 | V2EX、豆瓣电影正在上映 |

其中 **知乎日报、B站热门、GitHub 趋势、机核** 是原生实现（直接调官方 JSON 接口），比走 RSSHub 更快更稳。机核的原生实现还救了一个坑：它的 RSS 会被 WAF 拦掉，表现为"有时抓到有时抓不到"，改走官方 API 后就稳了。

### 第二层：需要一次登录态（Cookie）—— 需要你做一件事

| 平台 | 现状 | 你能做什么 |
|---|---|---|
| 知乎（某人的回答/文章/想法） | 无 Cookie 时接口**静默返回空数组**（不是报错，是假装没数据）；配好之后完全可用（已实测） | 提供一次 Cookie |
| 微博 | 无 Cookie 直接 432 / 403 | 提供一次 Cookie |
| 小红书等 | 还需要请求签名，工程量更大 | 优先级低 |

> 补充说明：知乎的 `/members/{token}/activities`（动态时间线）接口**现在对任何账号都返回空数组**，
> 即使登录态完全有效 —— 这是知乎的接口变更。所以这里改用了三个仍在正常工作的接口合并：
> `answers`（回答）、`articles`（文章）、`pins`（想法）。副作用是内容更干净了：
> 点赞、关注之类的噪声不会再混进来。

拿到 Cookie 之后，这些平台**同样能做成"输入名字就有结果"**，跟 B 站现在的手感一样。

#### 怎么配（设置页 → 登录信息，约 1 分钟）

1. 浏览器里打开并**登录**目标网站（zhihu.com 或 weibo.com）。
2. 按 **F12** → 切到 **网络 / Network** 面板 → **刷新页面**（F5）。
3. 点请求列表里**最上面那条**（就是网页本身）→ 右键 → **复制 → 复制为 cURL**。
4. 把这整段内容粘到设置页对应的输入框 → 点**保存并测试**。

几个要点：

- **一定用"复制为 cURL"**，不要用 `document.cookie`。`z_c0`、`SUB` 这些关键字段是 HttpOnly 的，
  只有前者能拿到。整段粘贴就行，程序会自己把 Cookie 挑出来
  （已支持 bash / cmd / `-b` / 多行 `^` 换行 / 只粘 Cookie 头 / 裸串等格式）。
- 输入框是密码型的，保存成功后**自动清空**，页面上不留痕。
- 测试结果会直接告诉你成没成：成功显示"已登录：你的昵称"。
- 如果显示"无效或已过期"→ 重新登录后再复制一次；如果显示被风控 → 告诉作者换接口。

**安全边界**（代码里怎么做的）：

- Cookie 只存在本地数据库 `instance/bai_read.db`，只发给它所属的平台，不上传任何第三方。
- 所有读取设置的接口一律**脱敏**：只回传"是否已配置 / 多少字符 / 结尾 4 位"，绝不回传原文
  （否则它会出现在浏览器网络面板和你的截图里）。
- 不写进任何日志。
- 不想用了随时点"清除"，或者去平台退出登录让它自然失效。

### 第三层：官方没有入口 —— 唯一的真难题

**微信公众号**：官方从来不给接口。可行的只有三条路，都不轻松：

1. 自建 wechat2rss（要有一个微信小号挂在那儿，把文章转进去）
2. 用第三方付费服务
3. 放弃批量订阅，只存单篇文章链接

我的建议是先放弃，或者等你真的离不开它时再单独处理。

### 顺带一提：自建 RSSHub 并不是"解锁一切"的钥匙

你机器上已经装了 Node v24.13.0（RSSHub 要求 ≥22），所以自建不需要 Docker，我可以帮你搭。但要想清楚收益：

- 它**能**给你更多平台的现成路由，省下我逐个写原生适配的功夫；
- 它**不能**绕过登录态——知乎、微博的路由一样要配 Cookie，配置起来比原生还麻烦；
- 它**不能**解决公众号；而且公共实例被限流的那些源，自建之后依然要自己维护。

所以我的建议顺序是：**先要 Cookie（第 2 层），再谈自建**。至于第 1 层，现在已经覆盖得不错了。

## 四、这一版做了什么

P0 全部做完：

- **订阅**：搜索即订阅、粘贴链接订阅、20 个预置源一键添加、删除（级联删文章）、暂停/恢复、单源刷新
- **文章**：时间倒序、未读加粗、阅读页正文提取、小圆点标记已读、全部已读、星标收藏、星标筛选、刷新进度条
- **存储**：SQLite（`instance/bai_read.db`），WAL 模式
- **视觉**：浅色/深色切换、卡片/列表两种视图、纯白极简

整理与检索（v0.1.4 新增）：

- **删除文章**：列表卡片上的 `✕` 或阅读页的 `🗑`。删错了有 **6 秒撤销**窗口。
  删除是**软删除** —— 记录会继续占着这篇文章的唯一标识，所以下次刷新**不会把它又带回来**
  （如果真删，源里那篇还在，刷新就会原样再插一遍，等于没删）。
- **收藏夹**：给收藏的文章分门别类，名字和颜色都能自定义。首页「星标」标签下会出现收藏夹条
  （全部收藏 / 未分类 / 各自的收藏夹 + 篇数），卡片上的 `📁` 或阅读页的「📁」按钮可以把文章放进去。
  放进收藏夹会**自动加星标**（否则它在收藏夹视图里看不见）。删收藏夹不会删文章，只会回到"未分类"。
- **搜索**：顶栏搜索框，同时搜**标题、摘要和正文**（所以能找回"那篇讲过某个东西的文章"）。
  搜索时**标题命中的排在前面**，命中词会高亮；在收藏夹里搜索就是在该收藏夹范围内搜。
  按 `/` 可以直接跳到搜索框，`Esc` 清除。
- **三种视图**（v0.1.6）：顶栏 ▦ 按钮循环切换，设置页也能选。
  - **网格卡片**（默认）：行列排布的**方形卡片**，上半是缩略图、下半是标题和来源时间。
    缩略图取正文里的第一张真实配图（B站封面、微博照片、少数派配图…），
    并会跳过表情、图标、占位图；没有配图的源用"来源首字 + 该源专属色"做占位块，同一个源颜色始终一致。
    标题最多三行，超出省略；操作按钮浮在图片右上角，悬停才出现。
  - **宽卡片**：原来的通栏卡片，标题显示最完整，适合细读。
  - **紧凑列表**：一行一篇，一屏看得最多。
- **侧边栏**（v0.1.5）：导航集中在左侧 —— 全部 / 未读 / 星标，下面是收藏夹列表（带颜色和篇数）。
  点「«」或按 `[` 收起，收起后列表能占满整个宽度；状态记在设置里，下次打开还是你上次的样子。
  窗口窄于 860px 时自动变成抽屉式（带遮罩，点空白处收起）。
- **多选批量操作**（v0.1.5）：点「☑ 选择」或按 `x` 进入，卡片左侧出现勾选框，工具栏换成操作条：
  标记已读 / 未读、加星标 / 取消星标、放入收藏夹、删除。支持"全选"（选中已加载的全部）。
  批量删除同样有**撤销**。`Esc` 退出多选。

P1 也顺手做了一部分：

- OPML 导入/导出
- 关键词过滤（在 SQL 层过滤，分页计数一致）
- 阅读页打印即导出 PDF（见下方说明）
- 每页文章数、自动刷新间隔可配置

额外加的（原文档没有，但用起来会想要）：

- **自动刷新**：默认每 30 分钟后台抓一次，可在设置页关掉
- **隐私模式**：一键屏蔽文章内所有图片，不看第三方图床
- **文章正文懒加载**：打开阅读页先出内容，正文异步补，绝不白屏
- **失败可见**：某个源抓取失败会在日志里留痕、界面上弹提示，连续失败 3 次自动暂停
- **播客音频**（v0.1.14）：播客源（有 `<enclosure type="audio/...">` 的源）在阅读页顶部给一个播放器，
  列表卡片上有 🎧 标记。音频地址单独存一列，不经过正文清洗。
- **数据导出**（v0.1.16）：设置页一键导出 JSON（全部数据表）或 Markdown 压缩包（每篇一个 .md）。
  **两者都不含登录信息**，可以放心拿去备份。

## 五、和原需求文档的差异（都是有意为之）

| 原文档 | 实际做法 | 原因 |
|---|---|---|
| Tailwind CSS 3.x | 手写 CSS，沿用文档里的同一套设计令牌 | 本地工具不需要构建步骤，也不想依赖 CDN。离线双击就能跑 |
| 微信/知乎/微博"搜索即订阅" | B 站做成原生搜索；知乎日报/机核/B站热门/GitHub 趋势做成原生接口；微博/知乎改成"粘贴主页链接"并给明确引导 | 实测这些平台的搜索接口要么需要签名+登录态，要么被限流，塞进一张路由表只会假装能用 |
| 全部依赖 RSSHub 公共实例 | 20 个预置源里 17 个零依赖；剩下 3 个（V2EX/豆瓣/36氪）走可配置+可探测的实例 | 实测 `rsshub.app` 在部分网络下完全不通，公共实例限流严重 |
| 正文提取放在阅读页同步做 | 抓取时能用 feed 自带全文或官方接口正文就直接用；没有的走异步提取，失败回退摘要 | 同步提取最长 10 秒，页面会白屏；知乎/微博这类站点提取基本必然失败 |
| `guid TEXT UNIQUE` | `UNIQUE(feed_id, guid)`，guid 缺失时用 `sha1(link\|title\|published)` 兜底 | 全局唯一会误吞文章；很多源根本没有 guid，空 guid 会让第一篇之后的文章全部静默消失 |
| 刷新接口里同步抓取 | 后台线程 + `/api/refresh/status` 轮询 | 10 个源 × 3 次重试 × 指数退避是分钟级的，同步做会把服务堵死 |
| WeasyPrint 导出 PDF | 阅读页"🖨"按钮 + 浏览器打印（另有 `@media print` 样式） | WeasyPrint 在 Windows 需要 GTK/Pango 原生库，安装很折腾；浏览器打印零依赖且效果不差 |
| `start.sh` | `start.bat` | 你是 Windows |
| "不使用 innerHTML 渲染 RSS 内容" | 服务端白名单清洗 + 前端 DOMPurify 二次清洗（DOMPurify 已本地化） | 正文本身就是 HTML，用 `textContent` 会把排版压成一坨纯文本。`innerHTML` 只喂清洗过的内容 |

## 六、已知限制（诚实说明）

1. **微信公众号没有稳定办法**，只能放弃批量订阅（见第三节第三层）。
2. **V2EX / 豆瓣 / 36氪 依赖公共订阅服务实例**，实测时好时坏。设置页有"检测"按钮可以挑一个能用的，也可以自己填。其余 17 个源完全不依赖它。
3. **B 站动态接口会随机返回空列表**（同一账号连续请求可能 13/0/13/0 条）。代码里做了重试，但偶尔仍可能一次抓不到，下次刷新就有了。
4. **知乎的文章正文接口返回 403**，所以专栏文章点进阅读页时才去提取（带着登录信息可以成功）；回答与想法的正文在抓取时就直接拿到了。
5. **微博会临时"软封"**：请求过于频繁时，它不报错，而是返回 HTTP 200 + `{"ok":-100,...signin}`，
   所有数据字段变空。**这通常几分钟到十几分钟会自己恢复**，不用急着重新复制 Cookie。
   程序现在能识别这种响应并如实告诉你原因（而不是笼统说"没有公开微博"）。
6. **微博按名字搜索取决于账号的搜索权限**，可能测试连接通过但搜不到人；粘贴主页链接那条路不受影响。
7. **`hnrss.org`（Hacker News）偶尔抽风**，一次请求可能要 12 秒甚至被重置；应用层有 3 次重试兜底。
8. 少数派等只给摘要的源，正文要打开阅读页时才去提取（约 1 秒）。
   提取是**两级**的：先 readability，太短就再试 trafilatura，都不行才回退显示摘要。
9. **靠 JS 渲染正文的页面（微博详情页、B 站 opus/视频页）提取不了正文** ——
   这些页面返回的 HTML 里只有一段脚本壳（实测微博详情页只有 549 字节），正文是浏览器执行脚本后才出现的。
   这不是提取库的问题：readability、trafilatura 都试过，**文字根本不在 HTML 里**，换谁都没用。
   这类条目阅读页会回退显示订阅源里的摘要 + 原文链接（点开原文即可）。
   真正能救回来的前提是"正文在 HTML 里、只是 readability 没认出来"，而这种情况实测并不多。
10. 单用户本地使用，**服务默认只监听 127.0.0.1**，同一局域网的其他设备访问不到（这是有意的安全默认）。
    想多端访问可以改 `BYREAD_HOST` / `BYREAD_PORT`（见第十一节），
    但**开放到局域网时请务必同时设置 `BYREAD_TOKEN` 访问口令** —— 否则你的数据库（含登录信息）就在那个网络里裸奔。
11. 没有移动端适配，桌面端优先。
12. **播客源的 feed 文件可能非常大**（实测 Syntax 单份 9.8MB），首次订阅和每次刷新的下载时间明显长于普通源
    （本机实测几秒到几十秒，取决于当时网速）。粘贴地址订阅时只读开头 1MB 做校验，所以订阅本身很快；
    但**正式抓取仍然要整份下载**，这是 RSS 的固有代价。播放器默认 `preload="none"`，不会因为排版就把整集音频拖下来。

**v0.1.20**

修**知乎回答的配图全部丢失**（截图里那篇《有什么是你去了洛阳才知道的事？》正文只有一半、一张图都没有）。

**根因**：早期版本把知乎接口返回的**截断正文**当完整正文存了下来。库里只记了"正文版本号"，
系统就以为它是完整的 —— 而刷新时"要不要重取正文"的判断正好是
`没有正文 或 版本号过旧`，两个条件都不成立，于是**永远不会再取一次**。
审计了全部 66 条知乎回答：**12 条是半截**（例：库里 1346 字 / 接口 6346 字，30 张图全丢）。

**这类问题的通用解法**（三层，任何平台都能照抄，已落进代码 + 回归测试）：

1. **判定**：抓取方发现内容不完整时，给条目加一个字段 `item["content_incomplete"] = True`。
   自己判断不了就用通用的 `feed_parser.looks_truncated()`（认结尾的"展开阅读全文 / read more"这类字样），
   或者用平台接口自己的标记（知乎的 `content_need_truncated`、微博的 `isLongText`）。
2. **表达**：db 层看到这个字段就写 `content_v = 0` 而不是当前版本号 ——
   直接复用已有的"这正文不可信、下次刷新重取"语义，**不新增字段**。
   误判的代价很小：至多下次多取一次，取回来没变化就把版本号推进到当前值。
3. **修复**：光"标旧"还不够 —— 刷新只能拿到最近 N 条，**老文章早滚出窗口了**，没人会去取。
   所以加了一条独立的修复通路：每个平台用
   `@content_refetcher("平台名")` 注册一个"给一条已入库的链接，把这一条的正文重新取回来"的函数
   （知乎：回答走 answers 接口、文章走 articles、想法走 pins 且会自动去取它分享的那条回答），
   刷新时顺带把该源"有正文但不可信"的老文章补一批（每次 6 篇，没欠账时一次请求都不发）。
   - 取回来的内容**只在确实更完整时才覆盖**（变短、图变少一律不覆盖）；
   - 抓取方明确说"这条没有可取的内容"（如回答已删）时记为已确认，不再每轮白试。

**结果**：12 条截断全部修复（审计 12/66 → **0/66**），16 篇的配图回来了 ——
`#426` 1346 字/0 图 → **6346 字/30 图**、`#438` 1579 → **7215 字/34 图**、
`#449` 1324 → **5642 字/26 图**、截图那篇 `#450` 2403 字/0 图 → **2901 字/3 图**。
阅读页实测这些图都在，且都走本地代理（zhimg 白名单），代理取回来的是真图（115KB JPEG）。

以后新订阅的源如果也遇到"正文被截断"，只要在对应平台模块里加一行判断（第 1 层）即可；
手工修某个源的全部正文：`python -c "import db; print(db.mark_content_stale(feed_id=27))"`，然后点一次刷新。

- 顺手修 3：**粘播客地址订阅后，源名会一直是域名**。搜索框粘贴地址时，候选为了秒回不去抓源，

  认不出"标题 == 域名"也是占位符，于是名字就永远停在域名上。
  现在把这种标题也当占位符 —— 订阅后第一次抓取完成就会变成真名（实测 `feed.syntax.fm` →
  `Syntax - Tasty Web Development Treats`）。

## 九、数据与隐私

- 所有数据在 `instance/bai_read.db`，复制这个文件就等于备份。
- **设置页 → 数据 → 导出**可以一键导出，两种格式都不含登录信息（见下条）：
  - **导出全部数据（JSON）**：订阅源 / 文章 / 已读星标 / 收藏夹 / 频道 + 频道与订阅源的对应关系，
    带 `format` / `version` / `exported_at` 头，软删除的文章也一并留着（备份要完整）。
  - **导出全部文章（Markdown）**：zip 压缩包，每篇文章一个 `.md`
    （标题 / 来源 / 作者 / 时间 / 原文链接 / 收藏夹 / 正文），适合存档或换设备读。
- **登录信息（Cookie）绝不进导出**，这和 `.gitignore` 排除 `instance/` 是同一条红线。做法是两层：
  导出白名单**逐表列明**（不是"遍历所有表"），`settings` 表不在其中；
  另外在出口处还会拿 Cookie 的真实值在产物里搜一遍，命中就中止下载并在日志里报错。
  所以这两个导出文件可以放心复制、备份、发给别人。
- 没有账号、没有云端同步、没有埋点、没有广告。
- 唯一的对外请求是抓你订阅的那些源，以及（可选的）搜索/解析其他平台时访问公共订阅服务实例。
- **图片走本地代理**：有些图床有防盗链，浏览器从 `127.0.0.1` 直连会被 403，
  所以这些域名（`sinaimg.cn`、`hdslb.com`、`zhimg.com`、`gcores.com`、`sspai.com`）的图片
  由本地服务带上**该站点自己的 Referer** 取回再转发。只允许这几个域名（顺带挡住把接口当内网扫描器），
  限制 3MB，内存缓存 6 小时。副作用是这些图床看不到你的浏览器直连（但仍然看得到你这个本地服务）。
  - 判断依据是实测出来的规则：**"不带 Referer 就 403、带上站点 Referer 才 200" 的图床必须进名单**。
    实测踩过：`cdnfile.sspai.com`（少数派配图）只要求"有 Referer"，不带就 403，
    而阅读页给所有图片加了 `no-referrer`，于是那篇文章的 71 张图全变成白框。
  - 名单的**唯一来源是服务端的 `IMAGE_PROXY_HOSTS`**，通过页面里的
    `<meta name="image-proxy-hosts">` 注入给前端（以前前后端各写一份，漏一个就是整页图片全挂）。
  - 还有一道通用兜底：图片直连失败时，会用 `referrerpolicy="origin"` 自动重试一次
    （Referer 只会是 `http://127.0.0.1:5000`，不泄露任何个人网址），仍失败才显示占位块。
  - 想知道当前订阅源里有没有"漏配"的图床，随时跑 `python tests/image_hosts.py`
    （它会实测库里每个图片域名，把需要 Referer 却没走代理的列出来）。
- 抓取时正文里的图片都加了 `referrerpolicy="no-referrer"`（少数派那类只在"完全不带 Referer"时才拦的图床
  走代理解决，见上）。想彻底不加载图片，设置页打开"屏蔽文章内的图片"。
- 文章里的脚本、iframe、`on*` 事件、`javascript:` 链接、隐藏元素、1×1 追踪像素在存库前就已被剥离。

## 十、遇到问题

| 现象 | 处理 |
|---|---|
| 打不开页面 | 确认 `python app.py` 那个窗口还开着，看有没有报错 |
| 某个源一直抓取失败 | 设置页看它的状态和失败原因（鼠标悬停在副标题上），连续失败 3 次会自动暂停，点"恢复"再试 |
| 搜索不到某个博主 | 换成粘贴他的主页链接 |
| 阅读页只有摘要 | 那个网站拦截了自动抓取，点"打开原文"，或点"再试一次提取" |
| 某篇文章正文明显不全 / 没有配图（其他同源文章正常） | 那一篇入库时可能只拿到了被源截断的半截正文。先点该订阅源的"刷新"（每次会顺带修复 6 篇）；想把某个源的正文全部重取一遍：`python -c "import db; print(db.mark_content_stale(feed_id=源id))"` 再刷新 |
| 想换订阅服务实例 | 设置页 → 高级 → 检测，挑一个可用的 |
| 某个源订阅失败，提示"暂时无法连接订阅服务"或"找不到" | 只有 V2EX / 豆瓣 / 36氪 这类源需要第三方实例。检查设置页 →「高级」→ 订阅服务实例：**留空 = 自动探测**；填了东西就点「检测」看它通不通（填订阅地址会被拒绝并提示） |
| 想备份 / 换电脑 | 设置页 →「数据」→ 导出全部数据（JSON），一个文件装全；想拿文章出去存档就用「导出全部文章（Markdown）」。两个文件都不含登录信息 |
| 想从头再来 | 关掉程序，删掉 `instance` 文件夹，重新启动 |
| 第一次启动时抓不到文章 | 确认网络能访问那些网站；首次抓取是后台跑的，看工具栏的进度条 |
| `git push` 报 `SSL certificate ... unable to get local issuer certificate` | Windows 上 git 的 OpenSSL 证书后端异常（实测：即使证书包完好也会报）。执行 `git config --global http.sslBackend schannel` 改用 Windows 系统证书库即可 |
| 某个源报 `SSL: CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate` | 本机有工具在做 HTTPS 中间人（例如 SteamTools 会把 `github.com` 的证书换成它自己的自签证书）。本项目已用 `truststore` 让 Python 改用系统证书库；若仍报错，执行 `python -m pip install truststore`。**更好的做法是在那类工具里关掉 HTTPS 拦截**，否则你的流量是被它解密中转的 |
| 双击 `start.bat` 一闪而过 | 用命令行 `cd /d 项目目录` 然后敲 `start.bat`，就能看到具体报错 |
| 中文在命令行窗口里显示成乱码 | `start.bat` 是 GBK 编码的，请用系统默认的 cmd 运行；如果你改过控制台代码页（`chcp 65001`），先改回 `chcp 936` |

## 十一、本地 AI 助手（测试版，默认开着）

这一版接了一个**跑在你自己电脑上**的小模型（Ollama + `qwen3:4b-instruct-2507-q4_K_M`），
只干一件事：**把你的一句人话翻译成"能搜的查询词"**。它不联网、不需要 API key，
你输入的内容不会离开本机。

### 怎么用（三个入口，随便挑一个）

| 入口 | 位置 | 适合什么 |
|---|---|---|
| ✨ 说一句 | 首页顶栏，「＋ 添加」左边 | 最直接：点一下，它会用示例句「帮我订阅半佛仙人」演示一遍 |
| ✨ 让本地 AI 猜一下 | 添加订阅弹窗里，**搜索没有任何确定结果时**才出现 | 你自己敲了一句话、搜不到东西的时候 |
| ✨ AI 实验室（测试版） | 设置页，在「高级」上面 | 想单独试句子、看模型原话、给它打分（见下面"参与测试"） |

### 它到底做了什么（以及**没有**做什么）

```
你说：帮我订阅半佛仙人
   ↓  正常搜索链（平台识别 + 两道闸门）—— 先走这里
「帮我」被句式闸门拦下 → 一个确定候选都没有
   ↓  这时候才叫本地模型
它说：platform=bilibili, keyword=半佛仙人（理由：明确提及B站UP主，把握 99%）
   ↓  拿"B站 + 半佛仙人"去问 B 站搜索接口（**真实返回**，它编不出不存在的账号）
候选 → 全部标成「⚠ 不确定」+「AI 猜的：…」，并且**默认收起来**
   ↓
你看到的：一句"这句话我没直接读懂，AI 猜你可能是想订 B站 · 半佛仙人" +
         一个「▸ 展开 3 个不确定的候选」+「✨ 本地 AI 的理解」+「用它再搜一次」
```

三条硬规矩（写在 `ai.py` 文件头，别改）：

1. **它不决定订阅**。有确定结果时根本不叫它 —— 免得它用错的猜测盖掉本来正确的命中
   （实测同一个模型把「少数派」猜成 `jike`）。
2. **它猜的候选一定是"不确定"**：带 ⚠ 标记、默认折叠、需要你点开才看得见。
   最终能不能订，仍然由搜索链和 P0 的两道闸门决定。
3. **它有自己的时间预算**（设置页可调，默认 6 秒），不占用解析链那 8 秒，
   链接类输入也完全不跑它 —— 所以"失败路径 ≤10 秒"这条验收不会被它弄破。

### 参与测试（你的反馈就是最有用的东西）

设置页 →「✨ AI 实验室（测试版）」：

- **检测 / 预热**：看模型在不在、加载了没有（冷启动 5~11 秒，热了 3~4 秒；
  应用启动时也会在后台预热一次）
- **试一句**：输入任意说法 → 摊开给你看「平台 / 名字 / 建议查询词 / 把握 / 理由」，
  还能展开**模型的原话**（JSON）—— 判断题是提示词的问题还是模型能力的问题
- **👍 理解对了 / 👎 理解错了（+ 正确答案）**：记在**本机**
  `instance/ai_feedback.jsonl`，一行一条，不会自动上传任何地方
- **📋 复制反馈 / ⬇ 导出反馈**：把这段直接贴给开发者，就是下一轮改提示词、
  补平台别名的依据

已知的坑（先说出来，省得你踩）：模型对**泛词**很敏感。如果你说的是
「我想追那个讲财经的B站up」这种没有具体名字的，它现在会老实回"没看出具体要订谁"
（这是对的，不是坏了）；而「少数派」这类**平台别名**它经常认错 ——
所以别名表还是得靠规则兜，AI 只在规则兜不住时出手。

关掉的话：设置页那个开关，或设置项 `ai_enabled=false`（关掉后所有 ✨ 入口都不再出现，
搜索行为与接 AI 之前完全一样）。

## 十二、给将来留的口子（现在都不影响使用）

这一版**没加任何功能**，只把将来"多端 / 托管"会用到的地方先留出来 ——
所以现在用起来和以前一模一样（验收就是照这个标准做的：刷新、添加订阅、阅读全部照常）。

**1. 监听地址可配置**（`app.py` → `_resolve_bind()`，默认不变：只监听本机 `127.0.0.1:5000`）

- 环境变量优先：`BYREAD_HOST` / `BYREAD_PORT`；也可以写进设置表的 `bind_host` / `bind_port`
- 想让手机访问就 `set BYREAD_HOST=0.0.0.0` —— **这时请务必同时设 `BYREAD_TOKEN`**，
  否则等于把整个数据库（包括你的登录信息）摊给同一个局域网里所有人
- 值不合法（比如端口写成 70000）会退回默认值并记一条日志，不会让程序起不来
- `start.bat` 也跟着 `BYREAD_PORT` 走：端口占用检测、屏幕上打印的地址、自动打开的网址

**2. 全局鉴权钩子**（`app.py` → `_auth_guard()`，**默认放行**）

- 不配口令时它就是一行 no-op（直接 return，连数据库都不查），本地自用与以前完全一致
- 配了口令（`BYREAD_TOKEN` 环境变量，或设置表 `access_token`）之后，**所有页面与接口**都要口令，
  而前端一行都不用改 —— 这就是做成全局钩子而不是逐个改路由的原因：
  - 浏览器：第一次访问 `http://host:port/?token=你的口令`，之后靠 HttpOnly Cookie 自动带上；
    登录成功后会 302 重定向到去掉 token 的地址，**口令不会留在地址栏和浏览历史里**
  - 脚本 / 将来的移动端：`Authorization: Bearer 你的口令`
  - 口令比对用 `secrets.compare_digest`（定时安全，防止逐字符试探）
  - `/static/` 与 favicon 免校验，否则登录页自己都加载不出来
- 实测两态都验过：默认态下 7 个入口全部放行；开了口令后无口令一律 401（页面给口令输入页、接口给 JSON），
  三种带口令方式都通，清掉 Cookie 又会被拦

**3. 本地源的平台注册表**（`feed_parser.py` → `LOCAL_FEED_HANDLERS`）

- 以前是一条 `if/elif` 长链，加平台得往链中间插一段；现在加平台 =
  写一个 `(parts, limit, content_state, feed_url) -> dict` 的函数 + 一个 `@local_handler("平台名")`，
  `fetch_local_feed` 只负责解析地址和查表
- 报错行为保持不变：平台不认识、或类型不认识，都是同一句 `未知的本地源类型：...`
- 已逐个验证：7 种 `byread://` 地址分派正确，5 种错写法报错信息与重构前一致

**4. 版本号 + 统一重处理入口**（`db.py` → `SCHEMA_VERSION` / `CONTENT_VERSION` / `sync_versions()`）

- 两个版本号现在是**设置项**（`schema_version` / `content_version`），在设置表里直接能看到
- 以后改了解析逻辑：`CONTENT_VERSION += 1`，启动时 `sync_versions()` 会自动执行
  `CONTENT_REPROCESS[新版本号]`。不挂函数就走默认动作：把老文章标为"待重取"，
  下次刷新按新逻辑重取 —— 也就是原来那套约定，现在从"各处心照不宣的写法"收进了一个地方
- **第一次见到某个库时只写版本号、绝不重处理**：否则每个老库升级后都会莫名其妙全量重取一遍正文
  （实测这条最容易出事，所以专门写了测试：版本记录缺失时 `content_v` 一篇都不许被动）
- 结构版本（`SCHEMA_VERSION`）走同一套机制，但**不会**去动正文
