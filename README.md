# 白读 · ByRead

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
![Python](https://img.shields.io/badge/Python-3.10%2B-blue)
![Platform](https://img.shields.io/badge/Platform-Windows-lightgrey)

给自己用的本地 RSS 阅读器。数据全在你自己的电脑上，不需要登录，没有推荐流，没有广告。

**核心体验**：你在一个输入框里输入博主名或平台名，它自己找到对应的源并开始抓文章。全程不出现"RSS""路由""订阅地址"这些词。

---

## 一、快速开始（怎么自己启动）

**最简单：双击 `start.bat`**（在 `E:\ByRead\` 目录下）

它会依次做四件事：检查 Python → 检查并安装依赖 → 启动服务 → 打开浏览器。
启动后那个黑色命令行窗口**就是程序本体，别关它**；要停止程序，关掉那个窗口或按 `Ctrl+C`。

如果它提示「**白读已经在运行了**」，说明已经有一个实例在跑（可能在另一个窗口里），
它会直接帮你打开页面，不会报错。

**或者手动启动：**

```bat
cd /d E:\ByRead
python app.py
```

看到 `白读已启动 → http://127.0.0.1:5000` 就成了，浏览器打开这个地址。

### 用起来更顺手一点

| 想要 | 怎么做 |
|---|---|
| 桌面快捷方式 | 右键 `start.bat` → 显示更多选项 → 发送到 → 桌面快捷方式 |
| 开机自动启动 | `Win+R` 输入 `shell:startup` 回车，把上面的快捷方式拖进去 |
| 停止程序 | 关掉那个命令行窗口，或在窗口里按 `Ctrl+C` |
| 备份数据 | 复制 `instance\bai_read.db` 这一个文件就够了 |
| 从零开始 | 关掉程序，删掉整个 `instance` 文件夹，重新启动 |

首页地址固定是 **http://127.0.0.1:5000**，只监听本机，同一局域网的其他设备访问不到。

首次启动会自动添加 3 个示例源（阮一峰的网络日志、少数派、Hacker News）并抓一遍，所以你打开就能看到文章，不是空页面。不想要就在设置页删掉。

环境要求：Python 3.10+（本机实测 3.14.2 正常）。不需要 Node，不需要 Docker，不需要联网构建。

## 三、"无感订阅"能做到什么程度

先纠正一个前提：**"无感"跟 RSSHub 没有必然关系**。RSSHub 只是一堆开源抓取脚本的集合，它做的事我们自己也能做（B 站、知乎日报、机核、GitHub 趋势现在都是原生实现，一次都没经过 RSSHub）。

真正决定"能不能无感"的，是**这个平台的数据从哪来、要不要登录态**。分三层：

### 第一层：自带官方源 / 官方接口 —— 完全无感，零依赖

现在预置的 20 个源里，**17 个属于这一层**，实测全部可用：

| 类别 | 源 |
|---|---|
| 科技媒体 | 少数派、IT之家、爱范儿、极客公园、雷峰网、钛媒体、Solidot |
| 技术博客 | 阮一峰的网络日志、酷壳、云风的 Blog |
| 开发者 | 掘金、GitHub 每日趋势、Hacker News |
| 游戏 / 亚文化 | 机核（文章+电台）、游研社 |
| 平台原生 | 知乎日报、B站热门 |
| 社区 / 影视 | V2EX、豆瓣电影正在上映 |

其中 **知乎日报、B站热门、GitHub 趋势、机核** 是原生实现（直接调官方 JSON 接口），比走 RSSHub 更快更稳。机核的原生实现还救了一个坑：它的 RSS 会被 WAF 拦掉，表现为"有时抓到有时抓不到"，改走官方 API 后就稳了。

### 第二层：需要一次登录态（Cookie）—— 需要你做一件事

| 平台 | 现状 | 你能做什么 |
|---|---|---|
| 知乎（某人的回答/文章/想法） | 无 Cookie 时接口**静默返回空数组**（不是报错，是假装没数据）；配好之后完全可用（已实测） | 提供一次 Cookie |
| 微博 | 无 Cookie 直接 432 / 403 | 提供一次 Cookie |
| 小红书等 | 还需要请求签名，工程量更大 | 优先级低 |

> 补充说明：知乎的 `/members/{token}/activities`（动态时间线）接口**现在对任何账号都返回空数组**，
> 即使登录态完全有效 —— 这是知乎的接口变更。所以这里改用了三个仍在正常工作的接口合并：
> `answers`（回答）、`articles`（文章）、`pins`（想法）。副作用是内容更干净了：
> 点赞、关注之类的噪声不会再混进来。

拿到 Cookie 之后，这些平台**同样能做成"输入名字就有结果"**，跟 B 站现在的手感一样。

#### 怎么配（设置页 → 登录信息，约 1 分钟）

1. 浏览器里打开并**登录**目标网站（zhihu.com 或 weibo.com）。
2. 按 **F12** → 切到 **网络 / Network** 面板 → **刷新页面**（F5）。
3. 点请求列表里**最上面那条**（就是网页本身）→ 右键 → **复制 → 复制为 cURL**。
4. 把这整段内容粘到设置页对应的输入框 → 点**保存并测试**。

几个要点：

- **一定用"复制为 cURL"**，不要用 `document.cookie`。`z_c0`、`SUB` 这些关键字段是 HttpOnly 的，
  只有前者能拿到。整段粘贴就行，程序会自己把 Cookie 挑出来
  （已支持 bash / cmd / `-b` / 多行 `^` 换行 / 只粘 Cookie 头 / 裸串等格式）。
- 输入框是密码型的，保存成功后**自动清空**，页面上不留痕。
- 测试结果会直接告诉你成没成：成功显示"已登录：你的昵称"。
- 如果显示"无效或已过期"→ 重新登录后再复制一次；如果显示被风控 → 告诉作者换接口。

**安全边界**（代码里怎么做的）：

- Cookie 只存在本地数据库 `instance/bai_read.db`，只发给它所属的平台，不上传任何第三方。
- 所有读取设置的接口一律**脱敏**：只回传"是否已配置 / 多少字符 / 结尾 4 位"，绝不回传原文
  （否则它会出现在浏览器网络面板和你的截图里）。
- 不写进任何日志。
- 不想用了随时点"清除"，或者去平台退出登录让它自然失效。

### 第三层：官方没有入口 —— 唯一的真难题

**微信公众号**：官方从来不给接口。可行的只有三条路，都不轻松：

1. 自建 wechat2rss（要有一个微信小号挂在那儿，把文章转进去）
2. 用第三方付费服务
3. 放弃批量订阅，只存单篇文章链接

我的建议是先放弃，或者等你真的离不开它时再单独处理。

### 顺带一提：自建 RSSHub 并不是"解锁一切"的钥匙

你机器上已经装了 Node v24.13.0（RSSHub 要求 ≥22），所以自建不需要 Docker，我可以帮你搭。但要想清楚收益：

- 它**能**给你更多平台的现成路由，省下我逐个写原生适配的功夫；
- 它**不能**绕过登录态——知乎、微博的路由一样要配 Cookie，配置起来比原生还麻烦；
- 它**不能**解决公众号；而且公共实例被限流的那些源，自建之后依然要自己维护。

所以我的建议顺序是：**先要 Cookie（第 2 层），再谈自建**。至于第 1 层，现在已经覆盖得不错了。

## 四、这一版做了什么

P0 全部做完：

- **订阅**：搜索即订阅、粘贴链接订阅、20 个预置源一键添加、删除（级联删文章）、暂停/恢复、单源刷新
- **文章**：时间倒序、未读加粗、阅读页正文提取、小圆点标记已读、全部已读、星标收藏、星标筛选、刷新进度条
- **存储**：SQLite（`instance/bai_read.db`），WAL 模式
- **视觉**：浅色/深色切换、卡片/列表两种视图、纯白极简

整理与检索（v0.1.4 新增）：

- **删除文章**：列表卡片上的 `✕` 或阅读页的 `🗑`。删错了有 **6 秒撤销**窗口。
  删除是**软删除** —— 记录会继续占着这篇文章的唯一标识，所以下次刷新**不会把它又带回来**
  （如果真删，源里那篇还在，刷新就会原样再插一遍，等于没删）。
- **收藏夹**：给收藏的文章分门别类，名字和颜色都能自定义。首页「星标」标签下会出现收藏夹条
  （全部收藏 / 未分类 / 各自的收藏夹 + 篇数），卡片上的 `📁` 或阅读页的「📁」按钮可以把文章放进去。
  放进收藏夹会**自动加星标**（否则它在收藏夹视图里看不见）。删收藏夹不会删文章，只会回到"未分类"。
- **搜索**：顶栏搜索框，同时搜**标题、摘要和正文**（所以能找回"那篇讲过某个东西的文章"）。
  搜索时**标题命中的排在前面**，命中词会高亮；在收藏夹里搜索就是在该收藏夹范围内搜。
  按 `/` 可以直接跳到搜索框，`Esc` 清除。
- **三种视图**（v0.1.6）：顶栏 ▦ 按钮循环切换，设置页也能选。
  - **网格卡片**（默认）：行列排布的**方形卡片**，上半是缩略图、下半是标题和来源时间。
    缩略图取正文里的第一张真实配图（B站封面、微博照片、少数派配图…），
    并会跳过表情、图标、占位图；没有配图的源用"来源首字 + 该源专属色"做占位块，同一个源颜色始终一致。
    标题最多三行，超出省略；操作按钮浮在图片右上角，悬停才出现。
  - **宽卡片**：原来的通栏卡片，标题显示最完整，适合细读。
  - **紧凑列表**：一行一篇，一屏看得最多。
- **侧边栏**（v0.1.5）：导航集中在左侧 —— 全部 / 未读 / 星标，下面是收藏夹列表（带颜色和篇数）。
  点「«」或按 `[` 收起，收起后列表能占满整个宽度；状态记在设置里，下次打开还是你上次的样子。
  窗口窄于 860px 时自动变成抽屉式（带遮罩，点空白处收起）。
- **多选批量操作**（v0.1.5）：点「☑ 选择」或按 `x` 进入，卡片左侧出现勾选框，工具栏换成操作条：
  标记已读 / 未读、加星标 / 取消星标、放入收藏夹、删除。支持"全选"（选中已加载的全部）。
  批量删除同样有**撤销**。`Esc` 退出多选。

P1 也顺手做了一部分：

- OPML 导入/导出
- 关键词过滤（在 SQL 层过滤，分页计数一致）
- 阅读页打印即导出 PDF（见下方说明）
- 每页文章数、自动刷新间隔可配置

额外加的（原文档没有，但用起来会想要）：

- **自动刷新**：默认每 30 分钟后台抓一次，可在设置页关掉
- **隐私模式**：一键屏蔽文章内所有图片，不看第三方图床
- **文章正文懒加载**：打开阅读页先出内容，正文异步补，绝不白屏
- **失败可见**：某个源抓取失败会在日志里留痕、界面上弹提示，连续失败 3 次自动暂停

## 五、和原需求文档的差异（都是有意为之）

| 原文档 | 实际做法 | 原因 |
|---|---|---|
| Tailwind CSS 3.x | 手写 CSS，沿用文档里的同一套设计令牌 | 本地工具不需要构建步骤，也不想依赖 CDN。离线双击就能跑 |
| 微信/知乎/微博"搜索即订阅" | B 站做成原生搜索；知乎日报/机核/B站热门/GitHub 趋势做成原生接口；微博/知乎改成"粘贴主页链接"并给明确引导 | 实测这些平台的搜索接口要么需要签名+登录态，要么被限流，塞进一张路由表只会假装能用 |
| 全部依赖 RSSHub 公共实例 | 20 个预置源里 17 个零依赖；剩下 3 个（V2EX/豆瓣/36氪）走可配置+可探测的实例 | 实测 `rsshub.app` 在部分网络下完全不通，公共实例限流严重 |
| 正文提取放在阅读页同步做 | 抓取时能用 feed 自带全文或官方接口正文就直接用；没有的走异步提取，失败回退摘要 | 同步提取最长 10 秒，页面会白屏；知乎/微博这类站点提取基本必然失败 |
| `guid TEXT UNIQUE` | `UNIQUE(feed_id, guid)`，guid 缺失时用 `sha1(link\|title\|published)` 兜底 | 全局唯一会误吞文章；很多源根本没有 guid，空 guid 会让第一篇之后的文章全部静默消失 |
| 刷新接口里同步抓取 | 后台线程 + `/api/refresh/status` 轮询 | 10 个源 × 3 次重试 × 指数退避是分钟级的，同步做会把服务堵死 |
| WeasyPrint 导出 PDF | 阅读页"🖨"按钮 + 浏览器打印（另有 `@media print` 样式） | WeasyPrint 在 Windows 需要 GTK/Pango 原生库，安装很折腾；浏览器打印零依赖且效果不差 |
| `start.sh` | `start.bat` | 你是 Windows |
| "不使用 innerHTML 渲染 RSS 内容" | 服务端白名单清洗 + 前端 DOMPurify 二次清洗（DOMPurify 已本地化） | 正文本身就是 HTML，用 `textContent` 会把排版压成一坨纯文本。`innerHTML` 只喂清洗过的内容 |

## 六、已知限制（诚实说明）

1. **微信公众号没有稳定办法**，只能放弃批量订阅（见第三节第三层）。
2. **V2EX / 豆瓣 / 36氪 依赖公共订阅服务实例**，实测时好时坏。设置页有"检测"按钮可以挑一个能用的，也可以自己填。其余 17 个源完全不依赖它。
3. **B 站动态接口会随机返回空列表**（同一账号连续请求可能 13/0/13/0 条）。代码里做了重试，但偶尔仍可能一次抓不到，下次刷新就有了。
4. **知乎的文章正文接口返回 403**，所以专栏文章点进阅读页时才去提取（带着登录信息可以成功）；回答与想法的正文在抓取时就直接拿到了。
5. **微博会临时"软封"**：请求过于频繁时，它不报错，而是返回 HTTP 200 + `{"ok":-100,...signin}`，
   所有数据字段变空。**这通常几分钟到十几分钟会自己恢复**，不用急着重新复制 Cookie。
   程序现在能识别这种响应并如实告诉你原因（而不是笼统说"没有公开微博"）。
6. **微博按名字搜索取决于账号的搜索权限**，可能测试连接通过但搜不到人；粘贴主页链接那条路不受影响。
7. **`hnrss.org`（Hacker News）偶尔抽风**，一次请求可能要 12 秒甚至被重置；应用层有 3 次重试兜底。
8. 少数派等只给摘要的源，正文要打开阅读页时才去提取（约 1 秒）。
9. 单用户本地使用，**服务只监听 127.0.0.1**，同一局域网的其他设备访问不到（这是有意的）。
10. 没有移动端适配，桌面端优先。

## 七、更新记录

**v0.1.12**

- 新增：**频道** —— 把订阅源分组，订阅源多了以后"全部"就不会变成大杂烩。
  侧边栏新增「频道」区：点 ＋ 新建（起名字、选颜色、勾选包含哪些订阅源，一个源可以同时属于多个频道），
  点频道名即只看该频道的文章，**再点一下取消**；把鼠标移到频道上会出现 ✎ 可改名 / 换色 / 调整包含的源。
- 频道是"**订阅源的分组**"，和"收藏夹（装文章）"是两个不同维度，两者互不影响。
  页面标题会显示成「体育 频道 · 未读」这样，所以频道能和 **全部 / 未读 / 星标** 叠加，

- **抓取后频道自动就是最新的**：频道本质是"这批源"的过滤器，刷新抓到的新文章立刻出现在频道里，
  不需要任何额外的同步逻辑。频道的未读角标也会跟着刷新。
- 删除频道**不会**删除订阅源和文章，只是解除分组。
- 修：频道列表接口原先没返回 `feed_ids`，会导致打开"编辑频道"弹窗时**所有订阅源都显示未勾选**
  （预勾选依赖这个字段）—— 被测试当场抓到。

**v0.1.11**

- 新增：**可以按订阅源搜索 / 只看某个来源**。

  表现为**列表有内容、但总数显示 0**。现在统计与列表用完全一致的 JOIN。
- 修：设置页 / 来源筛选条上的**篇数没有排除"已删除"的文章**（某源显示 16 篇，实际 13 篇）。

**v0.1.10**

- 修：**GitHub 每日趋势抓取失败**（报 `SSL: CERTIFICATE_VERIFY_FAILED ... unable to get local issuer certificate`）。
  根因不在代码：本机装了会做 HTTPS 中间人的工具（实测证书签发者是 `BeyondDimension` 的
  **SteamTools Certificate**），它把 `github.com` / `api.github.com` / `raw.githubusercontent.com`
  的证书换成了自己的自签证书。Windows 证书库里有它的根证书（所以浏览器和 git 都正常），
  但 Python 默认只认 certifi 里那份 Mozilla 列表，验不过就报错 —— 而 baidu、少数派、B站
  没被中间人，所以只有 GitHub 系域名出问题。
  现在引入 `truststore`，让 Python 也使用系统证书库，行为和浏览器一致。
  **没有关闭证书校验**（那才是危险做法），只是信任你系统本来就信任的证书。
- 修：**临时性失败不再把订阅源永久暂停**。微博的限流是十几分钟就自愈的，但自动刷新每 30 分钟
  试一次，攒够 3 次就把源标成"已暂停"，等微博恢复了它也再不会被重试——用户只能手动点"恢复"。
  现在把"限流 / 软封 / 登录态过期"归为临时失败：不计入失败次数、不暂停该源，
  而且一次失败就返回（不重试三次，免得加重对方限流）。本次也把因此被误暂停的两个微博源恢复了。
- 改进：`start.bat` 的依赖检查里加上 `truststore`，否则已经装过其他依赖的人不会自动补上它。

**v0.1.9**

- 修：补齐判定没要求"值真的变了"，标题里含 `<` 的文章因为脏标题规则每轮都被重复写入。
- 修：链接也会被"改对"（想法页 → 回答页），补齐逻辑现在同样会更新 `link`。

**v0.1.7**

  现在文件按 **GBK + CRLF** 存盘（无 BOM），已在模拟本机控制台代码页（936）的环境下验证两条分支。
  另外新增「**已经在运行**」检测：以前重复启动会抛 `[WinError 10048] 端口被占用`，看着像程序坏了；

## 九、数据与隐私

- 所有数据在 `instance/bai_read.db`，复制这个文件就等于备份。
- 没有账号、没有云端同步、没有埋点、没有广告。
- 唯一的对外请求是抓你订阅的那些源，以及（可选的）搜索/解析其他平台时访问公共订阅服务实例。
- **图片走本地代理**：微博/B站图床有防盗链，浏览器直连会被 403，所以这些域名（`sinaimg.cn`、
  `hdslb.com`、`zhimg.com`、`gcores.com`）的图片由本地服务带正确的 Referer 取回再转发。
  只允许这几个域名，限制 3MB，内存缓存 6 小时。副作用是这些图床看不到你的浏览器直连（
  但仍然看得到你这个本地服务）。
- 抓取时正文里的图片都加了 `referrerpolicy="no-referrer"`。想彻底不加载图片，设置页打开"屏蔽文章内的图片"。
- 文章里的脚本、iframe、`on*` 事件、`javascript:` 链接、隐藏元素、1×1 追踪像素在存库前就已被剥离。

## 十、遇到问题

| 现象 | 处理 |
|---|---|
| 打不开页面 | 确认 `python app.py` 那个窗口还开着，看有没有报错 |
| 某个源一直抓取失败 | 设置页看它的状态和失败原因（鼠标悬停在副标题上），连续失败 3 次会自动暂停，点"恢复"再试 |
| 搜索不到某个博主 | 换成粘贴他的主页链接 |
| 阅读页只有摘要 | 那个网站拦截了自动抓取，点"打开原文"，或点"再试一次提取" |
| 想换订阅服务实例 | 设置页 → 高级 → 检测，挑一个可用的 |
| 想从头再来 | 关掉程序，删掉 `instance` 文件夹，重新启动 |
| 第一次启动时抓不到文章 | 确认网络能访问那些网站；首次抓取是后台跑的，看工具栏的进度条 |
| `git push` 报 `SSL certificate ... unable to get local issuer certificate` | Windows 上 git 的 OpenSSL 证书后端异常（实测：即使证书包完好也会报）。执行 `git config --global http.sslBackend schannel` 改用 Windows 系统证书库即可 |
| 某个源报 `SSL: CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate` | 本机有工具在做 HTTPS 中间人（例如 SteamTools 会把 `github.com` 的证书换成它自己的自签证书）。本项目已用 `truststore` 让 Python 改用系统证书库；若仍报错，执行 `python -m pip install truststore`。**更好的做法是在那类工具里关掉 HTTPS 拦截**，否则你的流量是被它解密中转的 |
| 双击 `start.bat` 一闪而过 | 用命令行 `cd /d 项目目录` 然后敲 `start.bat`，就能看到具体报错 |
| 中文在命令行窗口里显示成乱码 | `start.bat` 是 GBK 编码的，请用系统默认的 cmd 运行；如果你改过控制台代码页（`chcp 65001`），先改回 `chcp 936` |
